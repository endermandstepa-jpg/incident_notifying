Release Notes — v0.1.0

Этот релиз представляет первую стабильную версию системы Emergency Alert Service, полностью переведённой на in-memory архитектуру без зависимости от базы данных. Основной акцент сделан на устойчивость, простоту развертывания и корректную работу Telegram-интеграции.

Общая архитектура

Все данные хранятся в памяти через InMemoryDatabase. Это упрощает запуск приложения и устраняет зависимость от внешней инфраструктуры.

Сохранена вся основная бизнес-логика: создание чрезвычайных событий, обработка геозон, отправка уведомлений и сбор ответов пользователей.

Управление чрезвычайными ситуациями

Реализован REST API для создания и управления событиями ЧС.

POST /api/events создаёт новое событие с параметрами:

title
messageText
priority
city
координаты центра зоны и радиус

После создания события система:

сохраняет событие в памяти
создаёт геозону
вычисляет пользователей в зоне поражения
инициирует отправку уведомлений через Telegram
Геолокационная логика

Добавлен GeoService, реализующий расчёт расстояния по формуле Хаверсина.

Он используется для определения, находится ли пользователь в радиусе чрезвычайной ситуации.

Это позволяет ограничивать рассылку уведомлений только релевантными пользователями.

Telegram-бот

Реализован Telegram-бот как основной пользовательский интерфейс.

Поддерживаемые команды:

/create_profile — создание профиля пользователя
/update_profile — обновление профиля
/delete_profile — удаление профиля
/status — проверка состояния системы

Профиль пользователя включает имя, координаты и Telegram ID. Все данные сохраняются в памяти.

Система уведомлений

При создании события система автоматически отправляет уведомления пользователям, попавшим в радиус ЧС.

Каждое уведомление:

сохраняется в памяти
имеет статус доставки SENT или FAILED
логируется в системе

Отправка реализована по принципу best effort: сбои Telegram API не влияют на работу основного сервиса.

Ответы пользователей

Пользователи могут отправлять ответы через Telegram:

Я в безопасности
Нужна помощь

Ответы сохраняются в UserResponse и связываются с последним уведомлением пользователя.

In-memory storage

Система использует InMemoryDatabase для хранения всех сущностей:

users
events
zones
notifications
responses

Данные не сохраняются между перезапусками сервиса.

Обработка ошибок и устойчивость

Система спроектирована таким образом, чтобы:

не возвращать HTTP 500 при внутренних ошибках логики
обрабатывать некорректные запросы безопасно
логировать ошибки без остановки выполнения
продолжать работу при сбоях Telegram API
Безопасность API

Добавлена защита API через API key.

Все запросы к /api/** требуют заголовок X-API-Key. При отсутствии или неверном ключе возвращается 401 Unauthorized.

API возможности

Доступные endpoints:

POST /api/events — создание события
GET /api/events — получение списка событий
GET /api/events/{id}/responses — ответы пользователей
GET /api/users — список пользователей
PUT /api/users/{id} — обновление пользователя
DELETE /api/users/{id} — удаление пользователя
Итог релиза

Версия 0.1.0 представляет собой минимально жизнеспособную, но полностью функционирующую систему оповещения о чрезвычайных ситуациях.

Ключевые характеристики:
геолокационная фильтрация пользователей
Telegram-бот как основной интерфейс
полностью in-memory архитектура
